## Image Download - Batch v1.0.1

Bug-fix release. All fixes have regression tests (`node --test docs/superpowers/tests/bug-regressions.test.cjs`) and were verified in Chrome with the unpacked extension.

### Scanning
- Image URLs containing commas in `srcset` (e.g. Cloudinary `w_300,c_fill`) are no longer split into broken URLs.
- Inline SVG CSS backgrounds (`url("data:image/svg+xml,…")`) are detected.
- Unloaded lazy images are no longer mistaken for tracking pixels; raw-HTML URLs keep their query strings and full extensions (`.jpeg`, `.tiff`).
- Full-resolution mode leaves signed CDN URLs untouched.

### Downloads
- Image URLs without an extension (e.g. `/media/abc?format=jpg`) now save with the correct image extension.
- Custom `{index}` naming, subfolders, and converted-file extensions are applied correctly per image.
- Transparent images converted to JPEG get a white background instead of black.
- Large ZIPs no longer drop images because of queued-request timeouts (fetches run 6 at a time); failed fetches are reported and empty ZIPs are not created.
- Percent-encoded SVG data URIs produce valid files in ZIPs.

### Popup and side panel
- Download menu, Preferences, many-files warning, and filter menus open correctly.
- Size and pixel-sort filters update as image dimensions load; selections survive filtering and sorting.
- Stop ends a scan immediately; broken images are not re-requested on every refresh.
- A saved size filter shows the Clear control; Clear resets the minimum-size inputs.
- `.tif` files match the TIFF filter and conversion; paths like `/v1.2/photo` no longer show a bogus type.
- Side panel follows the active tab; area capture works with the `activeTab` permission.

### Security and reliability
- Web pages can no longer open the extension UI without a user click.
- Settings migration no longer clears synced settings when the local write fails.
- Page highlights are replaced and cleaned up correctly, including inside shadow DOM.
